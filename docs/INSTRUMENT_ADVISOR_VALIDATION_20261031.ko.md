# 악기 추천 기능 검증 — 2026-10-31 KST

대상: PR #81 이후 main `2546afa584d662243cd48646a9100dba387cc74d`.
수정: [PR #82](https://github.com/raven-deadwire/RavenForge-Luthier-Intelligence/pull/82).
운영 Worker 응답 버전: `20261031-instrument-advisor-1`.
수정 후보 Worker 버전: `20261031-advisor-enquiry-2`.
브라우저 검사는 PR #82의 로컬 UI를 사용했다. 운영 Worker는 기존 배포본 그대로다. 따라서 새 Worker 수정의 실서비스 반영 결과는 이 기록에 포함되지 않는다.

## 판정 범위

실제 OpenAI가 답한 운영 Worker 요청, 저장한 실응답의 브라우저 재생, API를 모의 처리한 결정적 회귀 테스트를 구별했다. 운영 API의 HTTP 200은 문장 전체의 정확성을 보장하지 않는다. 이 검증은 고객에게 문의를 보내거나 주문을 접수하지 않으며, 수정 후보를 운영 환경에 배포하지 않는다.

기존 신규 브라우저 테스트 `tools/test_instrument_advisor.cjs`는 3개 언어 × 2개 화면 크기에서 동일한 EDDA → EMBLA 에보니 흐름을 모의 응답으로 검사한다. PR #77의 Claude 응답은 이번 OpenAI 검증 근거에 포함하지 않았다.

## 재현한 결함과 수정

| 결함 | 재현 | 수정 |
|---|---|---|
| 실행 중 추가되는 옵션이 Worker 카탈로그에 없음 | `neck_finish=neck_body`, `color_headstock=head_natural`, EDDA/GRAMR의 비기본 픽가드를 선택하면 서버가 옵션을 누락하거나 되돌리고 별도 견적 상태를 잃는다. 기본값 실응답 적용에서도 브라우저 선택값에만 `neck_finish`, `pickguard`가 존재했다. | 카탈로그 생성 단계에서 실제 `RavenForgePreview.configureTestOptions`를 실행하고 변경된 카테고리와 번역을 포함한다. 렌더링 코드는 Worker에 번들하지 않는다. 기존 가격 비교 테스트도 실제 런타임 확장을 포함하도록 수정했다. |
| 문의서에서 희망 색상·추가 요청 누락 | 색상과 추가 요청을 입력하고 문의서를 작성해도 요청의 configuration에 해당 필드가 없다. 서버도 필드를 제거했다. 4모델 × 3언어에서 재현했다. | 브라우저가 두 필드를 전달하고 서버가 각각 300/1,000자 이내의 고객 데이터로 보존한다. 데이터 안의 XML 구분자는 이스케이프한다. 가격 결정에는 사용하지 않는다. |
| 실패한 문의서 생성 재시도에서 편집기 누락 | 문의서 버튼 → 429 → 입력창의 같은 요청을 재전송 → 답변 성공. 일반 채팅만 생기고 편집·저장 영역이 없다. 4모델 × 3언어에서 재현했다. | 동일 요청 재시도에 한해 문의서 생성 의도를 유지한다. 다른 질문으로 바꾸거나 새 대화를 시작하면 유지하지 않는다. |

기존 모델 기본가나 옵션 가격, 지판 선택 범위, 픽업/EQ 의존성은 변경하지 않았다.

## 결정적 검사

- Worker 테스트: 34건 통과. 기존 32건에 문의서 데이터와 런타임 카탈로그 결함 재현을 추가했다.
- 페이지 핸들러·가격 계산 대조: 1,108개 옵션 전환 통과. 이전 1,048건은 런타임 카탈로그 확장을 누락한 기준이었다.
- `npm run check:catalog`: 통과.
- `wrangler deploy --dry-run`: 번들 성공. 실제 배포 아님.
- `tools/test_advisor_enquiry_regressions.cjs`: 12개 조합 통과. 모의 응답으로 12개 모델/언어 조합의 고객 입력 전달, 실패 후 재시도, 다른 질문 전환, 편집 텍스트의 정확한 다운로드를 검사한다.
- `tools/test_advisor_catalog.cjs`: 12개 조합 통과. 모의 응답으로 12개 조합의 비기본 넥·헤드 색상, 픽가드와 별도 견적 상태, 명시적 적용 전후 선택값을 검사한다.

기존 브라우저 검사도 신규 advisor 6건, 상담 UI 24건 및 PDF 다운로드 4건 모두 통과했다. 홈페이지의 EN/KO/DE 진입점 3개는 해당 언어의 `advisor=1` 상담창으로 연결됨을 확인했다.

원본 실패 로그와 수정 후 로그는 [evidence](evidence/instrument-advisor-20261031/)에 보존한다. 테스트 호스트는 Chromium 131 / Playwright 1.49.1이다. 제한된 실행 환경 때문에 로컬 HTTP 서버와 브라우저를 같은 네트워크 공간에서 실행하고, 외부 정적 스크립트는 HTTPS 프록시를 통해 전달했다. 테스트 전용 브라우저 연결 설정은 제품 파일에 반영하지 않았다.

## 실제 응답 및 브라우저 검사

4개 모델 × 3개 언어 × 추천·설명·비교·문의서 4단계 = **48회 실제 Worker 요청**을 기록했다. HTTP 상태 분포는 `{200: 48}`이다. 가격 도구 결과가 포함된 28개 응답은 원본 카탈로그의 전체 항목·번역명·총액과 대조했으며, 28개가 일치했다. 설명/문의서 응답은 도구를 부르지 않고 현재 구성 데이터를 이용할 수 있으므로 quote가 없는 경우를 가격 실패로 간주하지 않았다.

**별도 UI 4회와 미수락 문의서 3회를 합하면 실제 `/chat` 요청은 총 55회이며 모두 HTTP 200**이다. 운영 Worker를 경유한 실응답이며 OpenAI 제공자 내부의 요청 ID·원문 tool call은 공개 응답에 노출되지 않는다. 배포 설정과 버전으로 OpenAI 경로를 식별했다. 새 수정본의 운영 실응답 시험은 아니다.

별도로 모델명을 제시하지 않은 조건 기반 질문을 실제 브라우저에서 전송하고, 받은 응답의 적용 버튼으로 네 모델을 각각 선택했다. [실제 UI 기록](evidence/instrument-advisor-20261031/live-apply.json)에 요청·응답, 적용 전 구성 보존, 모델 전환, 표시 총액, 지판 렌더, 픽업/EQ/긱백 선택 대조 결과를 보존했다. GRAMR는 에보니 거절 검사와 별개로 **패시브 전자회로 + 프리미엄 긱백**을 검사한다. 수치 €2,200은 패시브 전자회로의 별도 확인 금액을 포함하지 않는 부분 견적이다.

ASKR의 에보니·EMG·Tone Capsule 추천을 수락하지 않은 상태에서 문의서를 만드는 실제 요청도 KO/EN/DE 각각 수행했다. 세 언어 모두 현재 웬지/Fishman 구성과 미수락 에보니/EMG 제안을 구분했다. [미수락 문의서 기록](evidence/instrument-advisor-20261031/unaccepted-drafts.json)에 원문을 남겼다.

실제 응답을 저장해 1440px/375px에서 재생한 **24개 UI 조합**은 [재생 기록](evidence/instrument-advisor-20261031/replay-report.json)으로 구별했다. 이 재생은 새 OpenAI 호출이 아니다. 지판·가격·명시적 적용·문의서 편집·UTF-8 텍스트 다운로드를 검사했다. 24개 조합 모두 전체 선택값 비교 1건씩 실패했고 나머지 검사와 페이지 오류 검사는 통과했다. 차이는 운영 응답에서 누락된 `neck_finish`(전 모델) 및 픽가드 기본 필드(EDDA/GRAMR)다. 이를 성공으로 덮지 않았다. 수정 후보의 별도 12개 카탈로그 회귀 테스트는 해당 필드와 별도 견적 상태의 보존을 검사한다.

원본 요청/응답은 [live-api](evidence/instrument-advisor-20261031/live-api/)에 있으며 [집계 JSON](evidence/instrument-advisor-20261031/summary.json)에 HTTP·가격·UI 실패를 보존했다. 모든 요청은 검증용 연주 조건을 사용하며 개인정보나 API 키를 포함하지 않는다.

기본 견적은 기본 긱백 포함, VAT 제외다. 화면·카탈로그 기준값은 EDDA €2,100 / EMBLA €2,550 / ASKR €3,200 / GRAMR €2,000이다. 에보니 지판은 EDDA·EMBLA·ASKR에서 +€50이며 GRAMR는 현재 로즈우드만 선택 가능하다. GRAMR의 에보니 변경 거절은 결함으로 처리하지 않는다.

## 설명 문장의 별도 판정

운영 실응답에서 다음 설명 문제를 관찰했다. 원본 응답은 `live-api` JSON 및 별도의 `live-apply.json`에 있다.

| 응답 | 관찰 | 구현과 대조 |
|---|---|---|
| `ko-EDDA / explain` | xPure 버퍼를 배터리 없이 쓸 수 있는 듯 설명 | `delano_buffer` 사양은 9V 배터리를 명시한다. 패시브 EQ와 전원이 필요 없는 버퍼는 같은 뜻이 아니다. |
| `de-EDDA / explain` | John East, Glockenklang, LHZ를 활성 EQ 대안으로 안내 | 해당 옵션은 현재 EDDA에서 선택 가능하지 않다. |
| `en-EMBLA / live-apply` | 후속 질문에서 패시브를 기본 전자회로라고 설명 | 같은 응답의 견적은 Zuta Bass Core를 선택하고 있다. |
| `en-GRAMR / compare` | 에보니 선택 거절 뒤 other/exotic 드롭다운을 안내 | GRAMR 지판은 현재 로즈우드만 노출되며 해당 선택지는 없다. |

재료와 음색의 관계를 강하게 단정하거나 페이지 번역명 대신 내부 옵션 ID를 쓰는 문장도 있었다. 일부 응답은 프롬프트의 1,500자 권고를 넘는다. 이 결과를 가격/선택값 테스트의 통과로 덮지 않는다. 위 자유 문장 오류는 동일 응답 기록으로 검토할 수 있지만, 같은 문장이 매번 재생성된다는 보장은 없다. 미검증 프롬프트 수정으로 해결됐다고 주장하지 않는다.

이 PR의 검증된 수정 범위는 위 세 가지 재현 가능한 구현 결함이다. 자유 문장에 대한 사실성·표현 품질 전체 통과나 배포 후 실응답의 개선을 주장하지 않는다. 운영 Worker에 수정본을 배포한 뒤 동일한 요청 기록으로 별도 실응답 확인이 필요하다.

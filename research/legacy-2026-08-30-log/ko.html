1. 이 연구일지가 기록하는 것

처음 도면을 그릴 때 가장 먼저 보였던 것은 바디와 헤드의 외형이었다. 그러나 실제 제작용 도면을 반복해서 수정하면서 중요도가 완전히 뒤집혔다. 악기의 silhouette보다 먼저 고정되어야 하는 것은 scale, nut, fret position, bridge의 기능적 기준점, string path, neck joint와 routing envelope였다.

세 프로젝트는 난이도가 서로 달랐다. 24프렛 수퍼스트랫에서는 CAD와 production drawing의 기본 규칙을 익혔고, ASKR에서는 37–34인치 멀티스케일과 복잡한 전자계통 때문에 부품 하나의 변경이 전체 geometry에 연쇄적으로 영향을 주는 문제를 겪었다. EMBLA에서는 보다 전통적인 34인치 플랫폼을 쓰면서도 헤드스톡, 넥 감각, 옵션 호환성을 하나의 설계 체계 안에서 정리해야 했다.

핵심 관점

A drawing is not an illustration. It is a system of dependent geometry.
도면은 악기의 그림이 아니라, 서로 의존하는 기준점과 가공 영역을 한 좌표계 안에서 검증하는 시스템이다.

2. Superstrat — CAD를 배우면서 설계 순서를 다시 세우다

첫 제작 도면은 25.5인치, 24프렛, 6-inline headstock, Gotoh 510 계열 트레몰로와 HSH 구성을 전제로 한 수퍼스트랫이었다. 초기에 외형과 부품 이미지를 배치하는 방식으로 접근했지만, 실측 하드웨어와 앞·뒤 view를 대조하기 시작하자 그림 자체가 맞아 보여도 제작 기준으로는 틀릴 수 있다는 사실이 반복해서 드러났다.

2.1 헤드머신: “모양”이 아니라 post와 screw가 기준이었다

초기 SG381-07 MGT 배치는 전면과 후면에 하드웨어 형상을 투영하는 방식으로 시작했다. 이 단계에서는 튜너 외형과 버튼의 방향이 눈에 잘 들어왔지만, 실제로 중요한 post center, fixing screw center, rear housing의 좌우 반전 관계가 충분히 통제되지 않았다.

Figure 1. 초기 헤드머신 투영안. 전면·후면 표현을 동시에 맞추려다 하우징과 고정나사 방향의 기준이 불명확해진 단계.

Failure case 01

전면에서 맞아 보이는 tuner geometry를 후면에 그대로 복사하면 실제 back view에서는 좌우가 반전된다. 작은 fixing screw 위치 하나가 틀려도 목재 타공 단계에서는 되돌리기 어렵다.

이후 전면도와 후면도를 별도의 그림으로 “예쁘게” 맞추는 대신, 같은 post center를 공유하고 rear housing만 view 기준에 맞춰 mirror하는 방식으로 재정리했다.

Figure 2. REV-G 전면 헤드: 너트와 현 기준선에서 포스트 위치 재검증.

RavenForge_Superstrat_24F_REV-G_FRONT_HEAD_PREVIEW.png

Figure 3. REV-G 후면 헤드: 동일 post를 기준으로 rear housing과 fixing screw 방향을 분리 검증.

Design rule

Front and rear drawings are not separate drawings. They are two views of the same geometry.

2.2 Deep tenon과 프론트 픽업은 같은 공간을 요구했다

프론트 픽업을 지판 끝에 최대한 가깝게 배치하고, 동시에 넥의 접합 면적을 늘리기 위해 deep-tenon 계열 구조를 검토하면서 공간 충돌이 발생했다. 넥 우드는 픽업 아래까지 이어지고 싶었고, 픽업 라우팅은 같은 영역을 제거해야 했다.

Figure 4. 프론트 픽업과 넥 포켓/tenon 경계 검토. 픽업을 전진시키는 만큼 neck wood의 유효 길이가 줄어든다.

RavenForge_Superstrat_24F_REV-N_front_tenon_detail.png

Failure case 02

“넥을 더 깊게 넣으면 강해진다”와 “넥 픽업을 더 앞으로 보낸다”는 두 목표를 동시에 극대화할 수 없었다. 결과적으로 tenon 길이, 픽업 routing depth, 해당 구간의 남는 목재 두께를 함께 봐야 했다.

2.3 볼트 수보다 clearance와 하중 경로가 중요했다

넥 조인트를 보강하려고 볼트 수를 늘리는 방향도 검토했지만, 후면 트레몰로 캐비티와 스프링 클로, 전면 픽업 라우팅 때문에 “빈 공간”처럼 보이던 영역이 실제로는 사용 불가능한 경우가 많았다. 아래 clearance check는 볼트 배열과 neck-pocket envelope를 별도로 겹쳐 본 검증 단계다.

Figure 5. Rear clearance check. 6볼트 배열 자체보다 body/neck-pocket 경계와 가공 여유를 먼저 검증한 단계.

REV-J_rear_clearance_check.png

Design rule

More fasteners do not automatically create a better joint. 클램핑 포스가 필요한 위치, 남는 목재 두께, 반대편 cavity의 존재를 함께 검토해야 한다.

2.4 파일이 열리지 않으면 geometry가 맞아도 도면이 아니다

수퍼스트랫 작업에서는 geometry 오류뿐 아니라 DXF 구조 자체가 AutoCAD에서 거부되는 문제가 반복됐다. 한 버전에서는 R12 table에 허용되지 않는 group code가 들어가 전체 drawing이 폐기되었고, 이후에는 duplicate handle과 entity class separator 문제도 경험했다.

Unknown group 74 for table on line 72
Invalid or incomplete DXF input — drawing discarded

Bad handle 1137: already in use
Class separator for class AcDbEntity expected

이후 호환성을 우선해 AutoCAD R12 ASCII 구조, 단순 LINE/CIRCLE/TEXT entity, 명시적 layer registration, 불필요한 handle과 polyline 제거 등으로 파일 생성 규칙을 보수적으로 바꿨다.

Design rule

Production drawing에는 두 종류의 정확성이 필요하다: geometrical correctness와 file integrity.

3. ASKR — 멀티스케일이 부품 간 의존성을 드러내다

ASKR는 37–34인치 5현 멀티스케일, 브리지 근접 픽업, 18V 전자계통과 확장 옵션을 전제로 했다. 수퍼스트랫에서 centerline 중심으로 해결되던 문제가 ASKR에서는 각 현의 scale line, 픽업 angle, bridge segment, string path, control cavity와 battery packaging까지 서로 얽혔다.

특히 배터리 박스는 작은 부품처럼 보였지만 가장 많은 재배치를 일으킨 요소 중 하나였다. 넥 포켓, body contour, tummy cut, control cavity, 향후 3-pickup keep-out 영역을 모두 피해야 했기 때문이다.

화면에서 박스가 body outline 안에 “들어가 보인다”는 것만으로 충분하지 않았다. 실제 rear contour 깊이, screw flange, router 접근, wiring bore까지 포함한 안전 여유가 필요했다.

Design rule

Electronics are mechanical packaging. 회로도에서 연결 가능한 부품도 body 안에서는 실제 부피와 가공 여유를 차지한다.

3.3 헤드스톡도 하우징 envelope까지 넣어야 했다

헤드머신은 post hole만 맞춘다고 끝나지 않았다. HB6 계열을 적용하면서 rear housing과 key의 실물 envelope를 넣자 헤드 외곽, 인접 tuner, string path 사이의 clearance가 다시 달라졌다.

Figure 10. HB6Y housing-safe 검토. post center뿐 아니라 실제 하우징 envelope와 현 경로를 함께 배치한 단계.

RavenForge_ASKR_REV_HB6Y_front_head_housing_safe.png

Design rule

Hardware change = geometry change. 튜너나 브리지를 교체하면 타공만 바뀌는 것이 아니라 주변 외곽과 현 경로도 다시 검증해야 한다.

4. EMBLA — “전통적인 34인치”도 단순하지 않았다

EMBLA는 ASKR보다 전통적인 34인치 5현 플랫폼이지만, 목표한 연주감과 헤드 디자인, 실물 하드웨어, 옵션 확장성을 동시에 맞추는 과정에서 다른 종류의 시행착오가 발생했다. 특히 특정 브랜드의 넥 감각을 reference로 삼더라도 프렛 수, heel width, fingerboard radius, joint 방식이 다르면 수치를 그대로 복사할 수 없었다.

4.1 Nut-to-post string path를 먼저 그려야 했다

초기에는 튜너가 헤드 외곽 안에서 균형 있게 배열되는지를 먼저 봤다. 그러나 실제로는 각 현이 nut witness point를 빠져나와 post center까지 어떤 각도로 이동하는지가 우선이었다. 굵은 B/E현과 얇은 D/G현은 같은 미적 대칭으로 취급할 수 없었다.

Figure 11. REV-I nut/string study. cyan line으로 실제 nut-to-post 경로를 강조해 straight pull과 post 배치를 재검토했다.

헤드 외형을 먼저 고정하면 post를 억지로 집어넣게 된다. 이후에는 Nut slot → string path → post center → housing → head outline 순으로 우선순위를 바꿨다.

Design rule

Reference ≠ specification. 레퍼런스는 목표 감각과 비율을 설명하는 도구이고, 실제 제조 치수는 현재 악기의 scale, fret count, heel, hardware에 맞춰 다시 계산해야 한다.

5. 세 프로젝트에서 반복된 실패 패턴

6. Production drawing과 작업용 template을 분리하게 된 이유

초기에는 하나의 master drawing에 모든 정보를 넣으려고 했다. 하지만 라우터 템플릿에는 배선 계획이 필요 없고, head template에는 rear control cavity 정보가 필요 없다. 정보가 많을수록 좋은 도면이 아니라 작업 단계에 필요한 정보만 남긴 도면이 안전했다.

  • Master Drawing — 전체 기준 geometry와 부품 간 관계 관리
  • Neck / Head Template — 외곽, nut, tuner, truss/reinforcement 중심
  • Body Routing Template — neck pocket, pickup route, bridge reference 중심
  • Rear Template — cavity, tremolo/spring 또는 battery route 중심
  • Pickguard Template — 실제 절삭 외곽과 opening만 유지
  • 1:1 Print Template — 출력 배율, tile overlap, crop mark를 별도 검증

Design rule

A good production drawing does not contain the most information. It contains the right information for the operation being performed.

7. 현재 결론 — 도면은 답이 아니라 가설이다

CAD에서 간섭을 모두 제거하더라도 실제 제작이 성공한다고 단정할 수는 없다. 목재의 개체차, router bit와 jig의 공차, 하드웨어 제조 편차, 조립 접근성은 실제 프로토타입에서만 확인할 수 있다. 따라서 현재 도면은 최종 답이라기보다 제작 전에 세운 가장 정교한 가설이다.

Prototype loop

CAD iteration → 1:1 template → physical prototype → measurement → revision

다음 검증 단계에서는 실제 neck-pocket fit, bridge/string alignment, tuner clearance, reinforcement 작동 범위, pickup routing depth, cavity wall thickness, 배터리 접근성, 무게 중심과 작업성을 측정하고 도면 revision에 다시 반영한다.

“The drawing is not the instrument.
It is a hypothesis about the instrument.
The prototype is the experiment.”
